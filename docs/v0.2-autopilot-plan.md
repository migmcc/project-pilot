# v0.2 Autopilot — Plan (planning only; no code)

> Planning artifact. **No runtime code is written in this run.** Branch in use is `main` (renamed
> from `run-i-done-gate` in the private-repo baseline run). Suggested implementation branch:
> `run-m-autopilot` (the "Run L" label was already used for the private-repo baseline).

## Goal

Let the user open VSCode in a new project folder that has an `idea.md`, run **one** command, and have
ProjectPilot drive the lifecycle automatically through the phases that need no human decision,
stopping at each real human gate with clear local instructions. Design is **agent-driven autopilot**:
ProjectPilot never calls Claude Code slash commands, never uses subprocess/network/GitHub API; it
only writes clear local instruction files that the VSCode agent (and the human) act on.

Charter unchanged: ProjectPilot orchestrates and enforces; it does not validate the idea (SkillLab
owns that), does not replace the A-team (execution engine) or AgentDesk (optional), does not execute
the project technically, installs nothing, runs no `/orchestrate init`, and does no push/tag/release.

---

## 1. New commands

| Command | Purpose |
|---|---|
| `pp start --idea <path> [--name N] [--dir D] [--force]` | Read the idea file; init `.project-pilot/status.json` if absent; then run the autopilot loop to the first stop; (re)write coordination files. |
| `pp continue [--dir D]` | Run the autopilot loop from the current state: perform consecutive AUTO steps; stop at the first human gate; (re)write coordination files. |
| `pp approve decision <APPROVED\|NEEDS_REWORK\|REJECTED> --reason "..." [--dir D]` | Friendly alias for `decision set` (records only; does NOT advance — `pp continue` advances). |
| `pp approve execution --reason "..." [--override] [--dir D]` | Friendly alias for `execution approve` (records AND advances `planning → execution`). |
| `pp approve done --reason "..." [--dir D]` | Friendly alias for `done approve` (records AND advances `final-validation → done`). |

Notes:
- The v0.1 commands (`init`, `status`, `validate`, `decision set`, `advance brief`, `brief import`,
  `advise-setup`, `check-ateam`, `execution approve`, `final-validation prepare`, `done approve`)
  **remain unchanged**. `pp approve *` are thin aliases over the existing approval commands — no new
  gate semantics, just a simpler surface. The autopilot loop reuses the existing command logic.
- Every state-mutating v0.2 command (`start`, `continue`, `approve *`) **regenerates** the
  coordination files from `status.json` (single source of truth) so they never drift.

## 2. State changes

- Keep `schema_version = 1` (additive optional fields only; load via `.get(...)`, per policy).
- Add one optional field: `idea_source: str | None` — the path the idea was read from (traceability).
- No other required state. The autopilot is **stateless logic over the existing phase + gate fields**
  (`decision`, `brief`, `setup_advice`, `ateam_check`, `execution_approval`, `final_validation`,
  `done_approval`). Coordination files live as separate `.md` files, not inside `status.json`.
- `history` continues to record events; `RUN_LOG.md` is a human-readable mirror of key events.

## 3. `NEXT_ACTION.md` format (always written by start/continue/approve)

```text
# ProjectPilot — Next Action

Project: <name> (<slug>)
Current phase: <phase>
Updated: <iso-timestamp>

## What ProjectPilot just did
- <auto steps performed this run, or "No automatic step was available.">

## Next action
<one clear next step — either "run `pp continue`" or the specific human/agent action>

## For the VSCode agent
<explicit, safe instruction; only ever safe `pp ...` commands or human SkillLab/A-team steps —
never push/tag/release/install>
```

Deterministic given state + a frozen clock.

## 4. `ACTION_REQUIRED.md` format (written ONLY when blocked on a human gate; removed when clear)

```text
# ProjectPilot — Action Required (human gate)

Project: <name> (<slug>)
Phase: <phase>
Gate: <gate description>
Updated: <iso-timestamp>

## Why ProjectPilot stopped
<this step needs a human decision/approval/artifact; ProjectPilot does not perform it>

## Required human action
<exact command(s), e.g.:>
- Run `/skilllab-start-project` with the idea, then `pp approve decision <...> --reason "..."`
- or `pp brief import <path-to-PROJECT_BRIEF.md>`
- or `pp approve execution --reason "..." [--override]`
- or do the technical work with the A-team, then `pp final-validation prepare`
- or `pp approve done --reason "..."`

## Boundary reminder
ProjectPilot does not validate the idea, execute the project, or install/run external tools.
SkillLab owns validation; the A-team is the execution engine; AgentDesk is optional.
```

When the project is not blocked (mid-auto or `done`), `ACTION_REQUIRED.md` is **removed** to avoid
stale instructions.

## 5. Stop rules

The autopilot loop stops (and writes `ACTION_REQUIRED.md`) when:
1. The current phase's exit needs a **human decision/approval/artifact** (see §6/§7).
2. The recorded decision is `NEEDS_REWORK` or `REJECTED` — never auto-advance; instruct rework.
3. The phase is `execution` — ProjectPilot never decides the technical work is complete.
4. The phase is `done` — terminal; no `ACTION_REQUIRED.md`.
5. State is missing or inconsistent — exit non-zero with a clear message (no partial advance).
6. The only way forward would be a forbidden/external action — STOP (never performed).

Progress/idempotency: each AUTO step advances the phase (finite phase set ⇒ no infinite loop).
Re-running `pp continue` at a stop is safe and idempotent (re-writes the same deterministic files).

## 6. Phases that may advance automatically

| Transition | Operation (existing) | Why safe/auto |
|---|---|---|
| `idea → validation` | `validate` | Deterministic; only emits the SkillLab prompt. |
| `validation → brief` | `advance brief` | AUTO **only after** an `APPROVED` decision is recorded. |
| `setup-advice → planning` | `advise-setup` | Deterministic advice; no decision, no install. |

## 7. Phases that require human approval (autopilot STOPS)

| Phase | Human gate | Resolved by |
|---|---|---|
| `validation` | SkillLab decision (idea quality is SkillLab's, not ProjectPilot's) | `pp approve decision <...>` |
| `brief` | The SkillLab-produced brief must be provided | `pp brief import <path>` |
| `planning` | Execution approval (A-team readiness or explicit override) | `pp approve execution --reason [...]` |
| `execution` | Technical work is the A-team/human's; completion is a human signal | `pp final-validation prepare` |
| `final-validation` | Final sign-off | `pp approve done --reason` |

## 8. Tests needed (stdlib `unittest`; RED-first in the implementation run)

- `start --idea` reads the file, inits state, runs to first stop (validation); missing file → error;
  existing state without `--force` → no clobber.
- `continue` from `idea` → stops at `validation`; `ACTION_REQUIRED.md` mentions `/skilllab-start-project`.
- `approve decision APPROVED` then `continue` → auto-advances to `brief`, stops (import needed).
- `approve decision REJECTED`/`NEEDS_REWORK` then `continue` → no advance; `ACTION_REQUIRED` reflects it.
- `brief import` then `continue` → auto `advise-setup` → `planning`, stops (execution approval).
- `approve execution` then `continue` → stops in `execution` (work-complete gate).
- `final-validation prepare` then `continue` → stops at `done` approval.
- `approve done` → `done`; `continue` → reports complete; `ACTION_REQUIRED.md` is absent/removed.
- `NEXT_ACTION.md` always present and deterministic (frozen clock; byte-identical).
- `ACTION_REQUIRED.md` present only when blocked; absent at `done`.
- `RUN_LOG.md` appends events in order.
- `approve *` aliases produce the same state as the underlying v0.1 commands.
- no-automation guard still green (no `subprocess`/`socket`/`urllib`/`requests`/`github`/`git push`…).
- determinism: generated `.md` files byte-identical under a frozen clock.

## 9. Risks

- **Auto-advancing past a human-critical point** (e.g. skipping real execution work). → `execution`
  is a hard stop; ProjectPilot never marks the build complete.
- **Stale `ACTION_REQUIRED.md`** misleading the agent. → regenerate/remove from state every run.
- **Agent runs a forbidden action** from instructions. → instruction files only ever name safe
  `pp ...` commands or human SkillLab/A-team steps; never push/tag/release/install.
- **Coordination files drift** from `status.json`. → `status.json` is the single source of truth;
  files are regenerated each run.
- **Scope creep into real automation** (subprocess/network to "just run it"). → charter + guard;
  agent-driven only.
- **Idempotency / log spam** on repeated `continue`. → AUTO steps gated by phase/gate; deterministic
  re-writes; consider de-duplicating identical trailing `RUN_LOG` lines.
- **Determinism vs timestamps** in `RUN_LOG`. → injectable clock; tests freeze time.

## 10. Out of scope (v0.2 autopilot)

- Any `subprocess`, network, GitHub API, or Anthropic/LLM API in the runtime.
- ProjectPilot calling Claude Code slash commands directly (agent-driven only).
- Auto-running SkillLab, the A-team, AgentDesk, or any external tool.
- Auto-importing the brief (the human provides the path).
- Auto-deciding that execution is complete.
- push / tag / release / package publication.
- New lifecycle phases (D5 stays the canonical set).
- External dependencies; pytest.
- Multi-project or parallel orchestration.

## Proposed end-to-end flow (illustration)

```text
pp start --idea idea.md      # init → validate → STOP at validation (decision needed)
#   (agent) /skilllab-start-project ... ; then:
pp approve decision APPROVED --reason "..."
pp continue                  # advance brief → STOP at brief (import needed)
pp brief import PROJECT_BRIEF.md
pp continue                  # advise-setup → planning → STOP (execution approval)
pp approve execution --reason "..." [--override]
pp continue                  # STOP in execution (do the work with the A-team)
pp final-validation prepare  # human signals execution complete
pp continue                  # STOP at final-validation (done approval)
pp approve done --reason "..."   # → done
```
